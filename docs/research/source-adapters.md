# Source adapters and tile formats

Survey written in M7 by the source adapters track (fourth session, `docs/parallel-tracks.md`) before building the adapters of `@vibeglobe/sources`. It covers how the studied engines model sources, tiling schemes, coverage, attribution and provider terms, their known failure modes, how they test adapters, and the approach chosen. Reprojection, layer composition, source chains and color harmonization belong to the main track: this survey records what the engines do there, and the main track's ADR records the choice. Decisions: [ADR 0030](../adr/0030-source-adapters.md) (adapters), [ADR 0031](../adr/0031-google-maps-platform-terms.md) (Google profile), [ADR 0032](../adr/0032-openstreetmap-tile-usage-policy.md) (OpenStreetMap profile).

Only open-source projects were studied, by reading the files named below; no code was copied.

## How the engines model sources

- **A source object per kind, with metadata on it.** CesiumJS's imagery providers carry `tilingScheme`, `rectangle`, `minimumLevel`/`maximumLevel`, `tileWidth`/`tileHeight` and a `credit`, and answer per-tile `getTileCredits`. OpenLayers sources carry a tile grid, a projection, `attributions` (static or a function of the view) and `attributionsCollapsible`. MapLibre sources are style JSON (`tiles`, `minzoom`, `maxzoom`, `bounds`, `attribution`, `scheme: tms`). All three validate little when the source is added: a wrong level range or bounds shows up as missing or misplaced tiles.
- **Tiling schemes.** Every engine special-cases Web Mercator and geographic (CesiumJS `GeographicTilingScheme` with two root tiles, OpenLayers `EPSG:4326` grids). Custom WMTS matrix sets are turned into a tile grid (OpenLayers `optionsFromCapabilities`, iTowns `WMTSSource`) and drawn through the map projection; CesiumJS draws only the two built-in schemes.
- **Coverage.** CesiumJS's `rectangle` and MapLibre's `bounds` stop requests outside the data; OpenLayers uses the tile grid's extent; WMTS `TileMatrixSetLimits` are honored by OpenLayers and iTowns, not by CesiumJS.
- **Asynchronous sources.** OpenLayers' Google source and CesiumJS's `Google2DImageryProvider` create a session first and only then become ready; PMTiles in MapLibre runs through a custom protocol (`pmtiles://`) that resolves the header and directories asynchronously behind a URL.

## Formats

- **WMTS.** KVP and RESTful encodings; RESTful templates carry `{TileMatrixSet}`, `{TileMatrix}`, `{TileRow}`, `{TileCol}`, `{Style}` and dimension names. ArcGIS publishes a 0.28 mm scale set whose top levels do not cover the world exactly next to a `GoogleMapsCompatible` set (recorded fixture `wmts-arcgis.xml`).
- **WMS.** One GetMap per tile; 1.3.0 uses `CRS` and, for EPSG:4326, latitude-first BBOX; 1.1.1 uses `SRS` and longitude first. OpenLayers' `TileWMS` requests a gutter and crops it, so labels drawn near an edge appear whole on both tiles.
- **PMTiles v3.** A 127-byte header, a root directory in the first 16 KiB, leaf directories, run-length entries, Hilbert tile ids; directories may be gzip-compressed; the maintained `pmtiles` library reads them with range requests and caches directories.
- **MBTiles.** SQLite with `metadata` and `tiles` (TMS rows), or the deduplicated `map` and `images` tables behind a `tiles` view. In browsers it needs SQLite compiled to WebAssembly (sql.js).
- **MVT.** Protocol buffers with layers, keys, values and zig-zag geometry commands; the `mvt-fixtures` repository lists valid, recoverable and fatal tiles (two of its fixtures, 051 and 057, carry the same geometry with opposite verdicts).
- **quantized-mesh** and the heightmaps are the main track's M4 terrain adapters; F235's conformance run waits for them.

## Known failure modes from the issue trackers, and how the design avoids each

| Failure                                                                                     | Seen in                                         | Avoided by                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WMS 1.3.0 EPSG:4326 requested longitude first, so the map appears rotated or empty          | Leaflet, CesiumJS and OpenLayers issue trackers | The BBOX writer orders axes by version and CRS; unit tests pin both orders against recorded 1.1.1 and 1.3.0 capabilities                                                   |
| Labels cut at tile edges of WMS layers                                                      | OpenLayers (why `gutter` exists), CesiumJS      | A default 32 px gutter cropped away; a browser test with a no-gutter control shows the labels cut without it and whole with it                                             |
| WMTS matrix sets that only look like Web Mercator (ArcGIS 0.28 mm) misplace tiles           | CesiumJS and OpenLayers issues                  | Every matrix is checked for scale, origin and size; only exact levels are used, and the set with the most exact levels wins                                                |
| `TileMatrixSetLimits` ignored, so requests go out for tiles that 404                        | CesiumJS                                        | Limits make those tiles no data before any request                                                                                                                         |
| Seams after reprojection, and tiles of other systems drawn as if they were Web Mercator     | CesiumJS, OpenLayers raster reprojection        | Adapters request EPSG:3857 or EPSG:4326 directly when offered (F227) and refuse other systems with a `needs-reprojection` error until the main track's reprojection exists |
| Missing or wrong attribution (static strings, credits not updated as the view moves)        | MapLibre and OpenLayers issues; Google's terms  | Every adapter declares its attribution; the Google adapter fetches viewport copyrights for settled views (OpenLayers' approach), never per frame                           |
| Session tokens expiring mid-use (Google)                                                    | OpenLayers and CesiumJS issues                  | Sessions are renewed a minute before `expiry`, and a 401/403 from an expired session renews it and retries once                                                            |
| Keys leaking into logs and error messages                                                   | Many trackers (keys in tile URLs)               | Keys only in URLs where the provider requires it (Google), with a redaction helper for every URL that reaches a log                                                        |
| Corrupted archives or tiles crashing the decoder                                            | PMTiles and MVT trackers                        | Every reader catches its errors: a broken archive is refused with a descriptive error, a broken tile is no data; each parser is fuzzed in the suites                       |
| Public OpenStreetMap servers blocking applications without a valid Referer or with bulk use | OSMF operations (blocked-tiles page)            | The OSM public profile requires an application identifier, keeps concurrency at 2, forbids prefetch and offline packaging                                                  |

## How the projects test their adapters

CesiumJS and OpenLayers test providers against recorded capabilities documents and mocked responses (`Resource` and `fetch` stubs), with a few opt-in live examples; OpenLayers keeps real-server capabilities (ArcGIS, OGC samples) in its test data, which this repository reuses as fixtures (credited in `packages/sources/src/__fixtures__/README.md`). MapLibre tests sources against local fixture servers and runs render tests. None has a shared, framework-free conformance suite that third-party adapters can run; loaders.gl comes closest with per-loader test data.

## Chosen approach

- **Adapters return the frozen `ImagerySource` contract plus `attribution` and `profile`** (`DescribedImagerySource`), so the engine consumes them unchanged and the main track reads the extra metadata when it builds credits and enforces profiles. Asynchronous preparation (capabilities, archive headers, sessions) happens in the async factory; per-tile asynchronous work (archive directories, sessions) happens in the adapter's own transport behind a pseudo URL. ADR 0030.
- **Maintained libraries where they exist:** `pmtiles` (BSD-3-Clause), `sql.js` (MIT), `txml` (MIT) for XML in workers, `fflate` (MIT) for KMZ, `pbf` (BSD-3-Clause) for protocol buffers. The MVT decoder itself is written for this repository because the maintained decoder accepts tiles the specification calls fatal and hides the raw tags needed to reject them.
- **A shared, framework-free conformance suite** (`@vibeglobe/sources/conformance`): tiled sources (metadata, addressing, coverage, zoom range, 404/500/timeouts/corrupted payloads, cancellation, attribution, profile rules) and parsers (expected output plus fuzzing).
- **Provider profiles** only switch features off, each mapped from a dated reading of the provider's terms (ADR 0031, ADR 0032).
