# Playground

Demo app that exercises every engine feature; also the bed for visual, scenario and performance tests.

## Rules

- URL parameters drive it in tests: `?backend=webgpu|webgl2`, `?depth=fragment` (forces WebGL2's fragment-written depth path, ADR 0005), `?lon=&lat=&zoom=&heading=&tilt=` (initial view), `?debug=1` (debug overlay), `?imagery=world|levels|border&session=` (Web Mercator tiles from the fixture tile server, M3; `&gpuBudgetMB=&ramBudgetMB=` set the cache budgets), `?assets=<path>/` (the worker program and base image from another base URL, F100) and `?scenario=` with `frame-loop` (benchmark frame loop), `two-globes` (two instances), `drag` (continuous drag for the `drag-*` benchmarks; `?level=` sets the coarsest surface level and so the tile count, `?gpuTiming=1` records GPU time per frame), `street-level-jitter` and `depth-range` (debug quads for F057 and F058, `src/scenarios.ts`). `?experiment=gpu-probes` runs ADR 0004 and 0005's GPU readback probes instead of a globe (`src/gpu-probes.ts`). `?experiment=offscreen&render=main|worker` is the F065 measurement mode (`src/render-experiment/`, `npm run bench:offscreen`): the engine on the main thread or in a worker with OffscreenCanvas, with input, frame and overlay instrumentation. `?quality=low|medium|high|ultra|auto` (`&qualityAdaptive=0`, `&governor={json}`), `?gpuLoad=N` (debug: N extra full-screen passes, F401), `?atmosphere=off|low|medium|high|ultra`, `?fog=0`, `?sun=<ISO time>` and `?haze=` load the quality page (`src/quality-demo.ts`, hooks in `window.vibeglobeQuality`). `?scenario=3dtiles-city` streams the fixture city through the 3D Tiles render extension (`&tiles3d=plain|draco|meshopt|ktx2`, `&tileset=`, `&sse=`, `&budgetMb=`, `&decoders=`, `&debug3dtiles`, `&tour=1`: an endless tour over the city for the `3dtiles-city` benchmark, `src/tiles3d-tour.ts`) and `?scenario=3dtiles-google` Google Photorealistic 3D Tiles over Rome (`&googleKey=` from the environment, never committed; `&googleRegion=eea|other`, `&googleBase=`, `&googleSessionMs=`), hooks in `window.vibeglobeTiles3d` (`src/tiles3d-demo.ts`, M13). `?vectorStyle=<name or URL>` draws a MapLibre style from the fixture vector tiles and `?scenario=mvt-*` sets a vector tile scenario's style and view, hooks in `window.vibeglobeVectorTiles` (`src/vector-tiles-demo.ts`). `?scenario=data-markers-lod` shows 100,000 markers with level of detail (`src/layers-lod.ts`, F374; `&debug=1` adds the overlay row of full, simplified and fading markers through `window.vibeglobeDebugRows`). `?scenario=live-feed` runs a feed of 10,000 position and color updates a second on a 100,000-point layer (`src/layers-live.ts`, F378, hooks in `window.vibeglobeLiveFeed`). `?custom=quadkey` attaches the imagery and terrain adapters of the consumer package outside `packages/` (`scripts/fixtures/custom-adapters/`, F219; tests answer its `https://quadkeys.test/` service from the fixture tile server, `src/custom-adapters.ts`). `?scenario=mont-blanc` shows real data to judge by eye (`src/mont-blanc.ts`): the Mont Blanc massif (45.8326° N, 6.8652° E, seen from the north over Chamonix) with Copernicus DEM GLO-30 terrain and ESA WorldCover Sentinel-2 imagery from the dataset pipeline's local sample builds, which `vite.config.ts` serves from `packages/tools/node_modules/.vibeglobe-data/<build>/output/` under `/real-data/` (never committed). Build them first, from the repository root after `npm run build`: `node packages/tools/dist/bin.js build packages/tools/configs/test-mont-blanc.json --sample --yes` (terrain, about 15 s, 165 MB downloaded, 11 MB written) and `node packages/tools/dist/bin.js build italy-high.json --sample --yes --dataset imagery` (imagery, about 40 s, 81 MB read with range requests, 1 MB written); the page names the missing ones instead of the view. When `world-low.json --sample` has been built too, its GLO-90 terrain and coarser WorldCover imagery surround the samples; elsewhere the Natural Earth base shows. The credits come from each `metadata.json` (Copernicus DEM licence, CC-BY-4.0 for WorldCover, `docs/data-licenses.md`). `&terrainBuild=<folder>` reads the terrain from another build folder (one made with `--out`), `&context=0` leaves out the world-low context. The italy-high imagery is clipped to Italy at levels 11 to 14 (the French and Swiss sides show level 10 only), and it is drawn as one layer per level, because a `noData` child hides a layer's coarser tile. `?network=online|hybrid|offline` wraps the fixture imagery with the offline engine (`@vibeglobe/offline`, loaded only then) in that network mode with every loading feature on, and `?debug=1` then shows the mode, connectivity and where tiles came from tier by tier (`src/offline-demo.ts`, F271, F272, F291, F292). Later milestones add their own and document them here.
- Tests and benchmarks read the page through `window.vibeglobePlayground` (`src/test-hooks.ts`), never through private state; its `mount()` creates and destroys extra instances for the leak suite.
- The page must load without console errors (`e2e/playground.spec.ts`).
- Workspace packages resolve to their TypeScript sources through the `source` export condition (`vite.config.ts`).

## Commands

- `npm run dev` (root) serves it at http://localhost:5173 (`PLAYGROUND_PORT` to change); `npm run preview -w @vibeglobe/playground` serves the production build at http://localhost:5176 (`PLAYGROUND_PREVIEW_PORT`), which the end-to-end tests of shipped bundles use.
- `npm run test:e2e` (root) runs the Playwright tests against it; `npm run bench` (root) runs the benchmark scenarios on its production build.
