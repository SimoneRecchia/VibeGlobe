# Offline, persistent storage and network adaptation

Survey written in M8, before the `offline` package is built on top of the RAM and GPU tiers from M3 ([`scheduling-and-caching.md`](scheduling-and-caching.md)). Decision: [ADR 0033](../adr/0033-offline-storage-and-network-modes.md).

## Scope and the requirements it serves

This survey covers storing tiles in the browser across sessions, offline packages, network modes, connectivity detection and bandwidth estimation. Requirements served:

- `PLAN.md`, Offline, online and caching: tier order GPU → RAM → persistent storage → packages → network; the two offline modes (a LAN server, a device with no network); quotas and eviction; persistent storage requests; health checks instead of the browser's online flag; bandwidth adaptation "like adaptive video streaming"; cache policy from headers and ETags; versioned packages; resumable installs and integrity checks.
- `PLAN.md`, Map sources: provider profiles switch off whatever the terms forbid (Google: no persistent cache; OpenStreetMap public servers: no offline packaging or bulk prefetch).
- Feature list: F271–F280 (tiers, persistent cache, quotas, eviction, persistence, headers, ETags, package versions, cache switch), F289–F299 (switches, network modes, offline modes, connectivity, seamless switching), F300–F303 (bandwidth estimation), F306–F313 (package integrity, resume, management), F318–F327 (provider rules).

Out of scope: request scheduling and RAM/GPU budgets ([`scheduling-and-caching.md`](scheduling-and-caching.md)), and the package builder CLI (`packages/tools`, a parallel track, [`data-pipeline.md`](data-pipeline.md)).

## How each project solves it

- **CesiumJS** has no persistent tile cache: it relies on the browser HTTP cache. Its offline guide says to swap ion and Bing for local providers, use the bundled low-resolution Natural Earth II imagery as a fallback base, disable the geocoder, and serve 3D Tiles from a local HTTP server. A 2015 proposal to cache tiles in IndexedDB was dropped after a slow proof of concept ([cesium#2459](https://github.com/CesiumGS/cesium/issues/2459)). No connectivity or bandwidth logic.
- **MapLibre GL JS** keeps no tile store of its own: the Cache API tile cache of Mapbox GL JS v1 (`tile_request_cache`) is gone from v6.15, and nothing replaces it. Expiry lives in memory: `setExpiryData` turns `Cache-Control: max-age` or `Expires` into an expiration time and arms a reload timer, falling back to exponential backoff when a server keeps sending already-expired tiles. On reload the worker compares the response ETag with the stored one and returns an "unmodified" result, skipping the parse. Revalidation itself (If-None-Match, 304) is left to the browser HTTP cache. Applications get offline behavior through `addProtocol` (the PMTiles adapter uses it).
- **MapLibre Native** has the most complete offline model. One SQLite database holds `resources` and `tiles` (key: URL template, pixel ratio, z, x, y; columns `etag`, `expires`, `modified`, `must_revalidate`, `accessed`, `data`, `compressed`) plus `regions` (a JSON definition: bounds or GeoJSON, zoom range, style) and link tables. Rows linked to no region form the **ambient cache**, bounded by `maximumAmbientCacheSize`; `evict()` deletes the 50 least recently accessed ambient rows per pass until the new size fits, and fails the write when it cannot (region rows are never evicted). `accessed` is updated on every read, under an index. A database found corrupt, "not a database" or moved is deleted and recreated; other errors are treated as temporary. Downloads skip resources already in the region (so restarting resumes), mark rows used in batches, count required against completed resources, cap the number of tiles, and retry errors after a delay rather than flooding the queue. `mergeDatabase` side-loads a pre-built database. `invalidateAmbientCache` marks rows for revalidation, so unchanged ones are not downloaded again.
- **OpenLayers** has no persistent cache or offline mode. Applications plug IndexedDB or a service worker in through `tileLoadFunction`; PMTiles comes through the external `ol-pmtiles` adapter.
- **PMTiles JS** reads archives with HTTP Range requests. It does not send `If-Match`, because Chromium then skips the browser cache, every request needs a CORS preflight, and the header is not CORS-safelisted. Instead it compares the response ETag with the header's and treats a 416 or a changed ETag as `EtagMismatch`: it invalidates its directory cache and retries once with `cache: "reload"`. Weak ETags are ignored. A 200 response to a Range request is accepted only if it is no longer than asked. On Chromium under Windows it fetches with `cache: "no-store"`, a workaround for a disk cache that returned zero bytes for range requests ([PMTiles#442](https://github.com/protomaps/PMTiles/issues/442)). Directory fetches are shared promises, aborted only when every caller has aborted.
- **go-pmtiles** `verify` checks the archive's structure: section offsets non-zero and in bounds, total length equal to the header's, counts of addressed tiles, entries and contents, zoom range and bounds. There is no content hash. `extract` copies a region or zoom range from a remote archive, merging nearby byte ranges within an over-fetch budget. `makesync` and `sync` hash blocks with xxHash64, so a new version transfers only the blocks that changed.
- **Shaka Player** (offline storage) keeps downloaded media in IndexedDB. It gives up on `open()` after a timeout, because sometimes no callback ever fires. It closes its connection on `versionchange` so other tabs can upgrade or delete. Each manifest is flagged `isIncomplete` until its download finishes, and on errors it calls `preventDefault()` so Firefox does not report them on the main thread.
- **Bandwidth estimation (all three players).** Each sample is bits ÷ seconds, weighted by its duration, and fed to two EWMAs (fast and slow). The estimate is the **minimum** of the two, so it falls quickly and rises slowly. The averages are bias-corrected while the total weight is small. Defaults: Shaka uses half-lives of 2 s and 5 s, ignores transfers under 16 kB and uses a default estimate until 128 kB have been sampled. hls.js uses 3 s and 9 s, a 500 kbit/s default, safety factors 0.95 (down) and 0.7 (up), and a separate EWMA for time to first byte. dash.js uses 3 s and 8 s, or arithmetic or harmonic means over a sliding window of 3 to 4 samples (resized by variance) as an option, with a 0.9 safety factor. All three discard cache hits: dash.js counts a response as cached when Resource Timing reports `transferSize` 0 and `decodedBodySize` > 0, and dash.js and Shaka also drop very fast loads (`cacheLoadThreshold(s)`).
- **Buffer-based and abandonment rules.** dash.js BOLA picks a quality from buffer level with a Lyapunov utility, plus a placeholder buffer at startup. It switches between throughput and BOLA rules dynamically. Its abandonment rule cancels a download when, after at least 6 throughput samples and 500 ms, the estimated remaining time exceeds 1.8 × the segment duration. hls.js runs its abandonment check every 100 ms: if the fragment will not finish before the buffer runs dry, it switches to a level that would.

## Browser storage: IndexedDB, OPFS and the Cache API

All three share one origin quota and are evicted together, as a whole origin, under storage pressure. They are all "script-writable storage" for Safari's 7-day rule.

**Quotas and eviction** ([MDN, Storage quotas and eviction criteria](https://developer.mozilla.org/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria); [WebKit, Updates to Storage Policy](https://webkit.org/?p=14403)):

- **Chromium:** an origin may use up to 60% of the disk. Best-effort origins are evicted least-recently-used first when the disk runs low, all of an origin's data at once. `persist()` is granted or denied silently, by heuristics such as engagement or an installed app.
- **Firefox:** best-effort storage gets 10% of the disk or 10 GiB per eTLD+1 group, whichever is smaller. Persisted storage gets up to 50% of the disk (MDN figure; not checked here). `persist()` shows a permission prompt.
- **Safari 17 and later:** 60% of the disk per origin in browser apps, 15% in other apps that embed WebKit, and cross-origin frames a share of their parent's quota. Since 17 it no longer prompts for more space. Persistent mode exempts an origin from eviction.
- **Safari ITP:** since 13.1, all script-writable storage (IndexedDB, Cache API, LocalStorage, service worker registrations) is deleted after 7 days of Safari use without user interaction with the site; Home Screen web apps keep their own counter ([WebKit, Full Third-Party Cookie Blocking and More](https://webkit.org/?p=10218)). A site visited weekly keeps its cache; a kiosk or rarely opened app may not.
- **Every browser:** a write over the quota fails with `QuotaExceededError`, delivered as a transaction `abort` or `error`, not a throw. Under disk pressure Chromium can report `AbortError` instead.

## How they test it

- **MapLibre Native:** gtest suites on real SQLite files, with fixtures for corrupt databases (immediate and delayed corruption), schema migrations v2–v5 and side-loading. Cases include: put evicts the least recently used rows; region rows never count against or get evicted from the ambient cache; a put fails when eviction is not enough; connection and server errors are not stored; read-only mode; disk full during a download; interrupt and resume; errors are retried; downloads do not flood the file source; a tile-count limit. There is a benchmark for the offline database.
- **PMTiles JS:** Node tests on fixture archives. They cover ETag change, header checks (empty file, magic number, future spec version), directory cache sharing, and abort semantics (cancel only when the last caller aborts). go-pmtiles has Go unit tests for extract, sync and directories.
- **Players:** unit tests for the estimators and rules: dash.js `ThroughputModel`, `BolaRule`, `AbandonRequestsRule`, `ThroughputRule`; hls.js `ewma-bandwidth-estimator` and `abr-controller`; Shaka `simple_abr_manager` unit and integration tests. They use synthetic sample sequences, not live networks.
- **CesiumJS, MapLibre GL JS, OpenLayers:** nothing for persistent storage or connectivity; MapLibre GL JS tests expiry timers with fake timers.

Nobody tests browser eviction, quota exhaustion in a real browser, or captive portals end to end. For VibeGlobe these become Playwright scenarios (F273–F275, F296–F298): a quota-limited context, storage cleared between reloads, `context.setOffline`, and a fixture server that answers tile URLs with a 302 or an HTML login page.

## Chosen approach for VibeGlobe

Full specification and defaults in [ADR 0033](../adr/0033-offline-storage-and-network-modes.md). In short:

1. **Tiers in order:** GPU → RAM (built in M3) → persistent cache → offline packages → network. Each tier is filled on the way back, as MapLibre Native's file-source chain does. Online-only mode skips packages; offline-only mode skips the network.
2. **Persistent cache in IndexedDB, owned by a dedicated worker,** so transactions and structured cloning stay off the main thread (the lesson of cesium#2459). Each record holds source id, tile coordinate, bytes (ArrayBuffer), content type, stored and expiry times, ETag and Last-Modified, and last access. An `accessed` index and a stored byte total give LRU eviction down to the configured limit (MapLibre Native's ambient cache, without the start-up scan of #1815).
   - A `QuotaExceededError` logs one warning, evicts, and never breaks rendering.
   - IndexedDB over OPFS: OPFS needs a separate index anyway, its fast handles exist only in workers, and Safari's support is younger.
   - IndexedDB over the Cache API: the Cache API is keyed by Response, has no metadata or LRU index, accounts size opaquely, and `keys()` fails at scale (#12965).
3. **Eviction detection:** a marker record and a localStorage list of what should exist are checked on open; IndexedDB `close` and `versionchange` events are handled while open. An event reports what was lost, and loading falls back to the other tiers. `navigator.storage.persist()` and `persisted()` are exposed, reporting granted, persisted or `'unsupported'`.
4. **Cache policy from HTTP headers,** as MapLibre GL JS and Native parse them: `Cache-Control` max-age, no-cache and no-store, `Expires`, `ETag`, `Last-Modified`.
   - `no-store` responses are never persisted.
   - Per-source overrides and provider profiles can only shorten lifetimes or forbid storage.
   - Expired tiles are revalidated with `If-None-Match` (or `If-Modified-Since`), and a 304 reuses the stored bytes. Cross-origin hosts must allow that header in CORS (PMTiles avoids `If-Match` for this reason). Hosts that do not get a plain re-fetch whose ETag is compared, as PMTiles and MapLibre's worker do.
5. **Offline packages:** PMTiles or MBTiles files with a JSON manifest (id, version, sources with license and attribution, area, files with bytes and SHA-256 plus per-chunk SHA-256).
   - Storage: packages live as chunked Blobs in IndexedDB, or are read from a LAN HTTP server with Range requests.
   - Integrity: on install, the whole file and its structure are checked (go-pmtiles `verify`, plus content hashes go-pmtiles does not have); on read, each chunk is checked, and corrupted tiles count as missing.
   - Installs resume: chunked downloads with HTTP Range and stored progress, skipping chunks already verified (MapLibre Native's skip-existing resume, go-pmtiles' block hashing).
   - A new version replaces the old version's tiles.
6. **Network modes** online-only, offline-only (never touches the network, not even health checks) and hybrid (the default). The loading switches (persistent cache, memory reuse, prefetch, offline packaging) apply globally, per source or per layer, and change at runtime. Provider profiles can only switch features off.
7. **Connectivity from health checks against the tile endpoints themselves:**
   - A check fetches a known tile and expects a 2xx with the expected content type and no redirect, so captive portals and HTML login pages count as unreachable.
   - Checks run per endpoint, at most one per interval, with exponential backoff while offline.
   - `navigator.onLine` and the `online` and `offline` events are only hints that trigger a check.
   - While an endpoint is offline, cache misses are not sent to it (no request storm, no error flood).
8. **Bandwidth estimation (main session):** throughput from measured tile downloads with a fast and a slow EWMA, taking the minimum, bias-corrected, ignoring cache and storage hits and very small samples, as Shaka, hls.js and dash.js do. Video's buffer-based rule (BOLA) and abandonment have a tile equivalent in M3's cancellation of unwanted requests and in the motion-aware detail level; they are not copied as such.

## Open questions

- Throughput from many small concurrent tiles: is per-request bits ÷ (responseEnd − responseStart) enough, or must the estimator aggregate bytes over a time window across all in-flight requests (closer to how a link is actually shared)? Cross-origin tile hosts without `Timing-Allow-Origin` hide Resource Timing sizes.
- Whether a persisted origin is also exempt from Safari's 7-day cap; WebKit's posts do not say so explicitly. Must be checked on a device (owner-only; `docs/internal/open-questions.md` if it blocks).
- The Safari release that ships OPFS `createWritable` (WebKit 254726 closed as a duplicate of 283841 in 2025); relevant only if OPFS is reconsidered for large packages.
- Whether package chunks on Safari should be ArrayBuffers instead of Blobs, given WebKit 235687/240216. Measure memory and reliability during M8 device tests.
- Default health-check interval and backoff cap, and how a check tile is chosen for sources without a known always-present tile (level 0 is the default).
