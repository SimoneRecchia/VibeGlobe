# Known bugs

Every bug found is listed here until it is fixed, and stays listed afterwards as a record. Rules (`PLAN.md`, Correctness):

- A fix starts with a failing regression test that reproduces the bug; the test is named below.
- No known bug may remain open at the end of a milestone, and a release ships with none open.

| KB-001 | The `local/no-commented-out-code` lint rule never reported anything, so commented-out code passed `npm run lint`. Root cause: it called `tseslint.parser.parse`, which does not exist (the parser exposes `parseForESLint`), and its `catch` treated the resulting `TypeError` as "not code". Found in M1 before the rule was first committed.                                                                                                     | Put `// const old = legacy();` above any statement in a `.ts` file and run `npm run lint`: no error.                         | Fixed (M1)                                                                                                                                   | `scripts/eslint/no-commented-out-code.test.ts` ("flags …" cases and the `invalid` RuleTester cases)                                           |
| KB-002 | After a package's `dist/` folder was deleted, `npm run build` did not rebuild it, so the package could not be resolved (`npm run check:consumer` and `npm run size` failed) and stale outputs of deleted sources stayed in `dist/`. Root cause: `tsc -b` kept its build info in `tsconfig.tsbuildinfo` next to the tsconfig, outside the output folder, and considered the project up to date. Found in M1 while running every documented command. | Run `npm run build`, delete `packages/vue/dist`, run `npm run build` again: `packages/vue/dist` is not recreated.            | Fixed (M1): build info lives in `dist/tsconfig.tsbuildinfo` (excluded from the published files)                                              | `scripts/checks/checks.test.ts` ("reports build info kept outside the output folder (KB-002)"), enforced on the repository by `npm run check` |
| KB-003 | The feature-list guard crashed (`git show` error) when its base revision predated `feature_list.json`, as on the first pull request into `main`, so CI's lint job would fail. Found in M1 while opening that pull request.                                                                                                                                                                                                                         | `node scripts/check-feature-list.ts --base 5ae4c9d` (the first commit, with only `PLAN.md`): exit 1 with a `git show` error. | Fixed (M1): such a base is skipped and the list is still compared with its first committed version; an unknown revision is an explicit error | `scripts/checks/feature-list-history.test.ts`                                                                                                 |
