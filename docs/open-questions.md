| 18  | **F064 with a rendering library that allocates per frame.** three.js 0.186 allocates about 5.6 KB per rendered frame internally, so a steady-state trace cannot be free of garbage-collection events. What does "no GC pause" mean?                                                                                                                                         | The engine's own code allocates zero bytes per frame (Node and Chromium tests). "No GC pause" means no main-thread collection pause of 8 ms or more (half a 60 Hz frame) in 60 s of motion, with a budget of 8 KB per frame for the library's garbage. Removing the library's garbage is a follow-up                                                                                                                                   | ADR 0018, F064          |

| 21  | **KTX2 transcoder toolchain and size (F104).** ADR 0020 planned an Emscripten build of at most 150 KB gzip; no Emscripten toolchain could be installed in the build container, and no combination of the upstream feature switches brings the transcoder of ETC1S, UASTC and the BC, ETC2 and ASTC targets under 150 KB (one build per format family: 170 KB for BC alone). | Build with a pinned wasi-sdk 25 (checked by hash) instead of Emscripten: a reactor module with a plain C interface, no JavaScript glue and five stubbed WASI imports; one build of 204 KB gzip, loaded lazily, gated at 210 KB by `npm run size` and rebuilt nightly against the committed hash.
