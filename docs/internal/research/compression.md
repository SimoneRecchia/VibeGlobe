# GPU texture compression and compressed geometry

- Status: Complete (survey for M3)
- Date: 2026-10-21
- Decision: [ADR 0020](../adr/0020-texture-and-geometry-compression.md)

## 1. Scope and requirements

This survey covers two things:

- **GPU texture compression:** imagery and other textures kept in a block-compressed format on the GPU (BC, ETC2, ASTC), delivered as KTX2 files that carry Basis Universal "supercompressed" data (ETC1S or UASTC) and are transcoded at load time to whatever block format the device supports.
- **Compressed geometry:** vertex and index data delivered compressed (Draco, meshopt) and decoded before upload.

For each, it covers how files are produced, where they are decoded or transcoded, how decoders are loaded, how the result is uploaded to the GPU, and how memory is counted.

Requirements it serves:

- **PLAN.md, Tiles, level of detail and streaming:** "GPU texture compression (for example KTX2/Basis) where it reduces memory and upload time". Feature **F104**: "GPU-compressed textures (KTX2/Basis) are used where supported to reduce memory and upload time, with a fallback where they are not." Its steps ask for a KTX2 fixture source, compressed uploads with lower GPU memory per tile on a supporting device, correct rendering through a transcoded fallback elsewhere, and measurements recorded in the ADR.
- **PLAN.md, Engineering standards, "Network efficiency":** compact binary formats and compression.
- **[ADR 0007](../adr/0007-scheduling-and-caching.md):** a priority-ordered upload queue drained each frame within **2 ms and 8 MB**, predicted by a per-backend cost model; items larger than the byte budget are uploaded in slices (rows or mip levels). GPU and RAM budgets are hard caps with **exact byte accounting**; the RAM tier keeps encoded bytes so the GPU copy can be rebuilt after a loss.
- **[ADR 0010](../adr/0010-renderer-base.md):** three.js `0.186.1` (`WebGPURenderer` with its WebGL2 fallback), imported only inside `packages/renderer`; uploads go through `renderer.initTexture()`; bytes are checked against `info.memory.texturesSize`.
- **[ADR 0011](../adr/0011-workers.md):** WebAssembly runs only in workers. Decoders are separate, content-hashed, same-origin module files loaded from configurable URLs (`assets.workerUrl`, `assets.wasmBaseUrl`). No `blob:` or `data:` workers, no `eval` or `new Function`, no CDN fallback. Only the worker needs `'wasm-unsafe-eval'`, carried by its own response headers. The worker program stays at or below **100 KB min+gzip**, excluding lazily loaded WebAssembly. If WebAssembly compilation is refused, the engine uses a JS fallback or reports a typed "format unsupported" error.
- **[ADR 0006](../adr/0006-level-of-detail.md) and [ADR 0013](../adr/0013-reconcile-m1-decisions.md):** workers turn every terrain source into a height grid and build per-tile float32 vertex buffers with shared index buffers. Terrain geometry is generated by the engine, not downloaded as meshes.
- **Licensing (CLAUDE.md):** third-party code must be permissively licensed (MIT, BSD, Apache-2.0, ISC). Code from other engines is studied, never copied.
- **Milestones:** compression of imagery lands in M3 (step 7, "KTX2/Basis transcoding where the device benefits"). glTF models arrive in M10 and 3D Tiles in M13, which is where compressed geometry first matters.

## 3. How each project solves it

### Basis Universal (encoder and transcoder)

- **Codecs.** v2.50 has eight codecs. The two that every web engine supports are **ETC1S** (a supercompressed subset of ETC1: small files, low to medium quality, very fast transcoding) and **UASTC LDR 4x4** (an ASTC-like 8 bits-per-pixel format: high quality, larger files, usually with rate-distortion optimization (RDO) followed by Zstandard). The newer XUASTC LDR, XUBC7 and HDR codecs are recent and not yet handled by the studied engines, except loaders.gl.
- **Transcoder API** ([`basisu_transcoder.h`][bu-h]). `ktx2_transcoder::init()` parses the container, `start_transcoding()` decodes the ETC1S global codebooks ("not free, so try to avoid calling it excessively"), and `transcode_image_level(level, layer, face, out, out_size, fmt, …)` writes one level in the target format. It is **not thread-safe** unless each thread passes its own `ktx2_transcoder_state`. For Zstandard-supercompressed UASTC arrays the header asks callers to finish one mip level before moving to the next, because each level is decompressed as one unit. `basisu_transcoder_init()` builds lookup tables once per process.
- **Targets** (`transcoder_texture_format`): ETC1 RGB, ETC2 RGBA, BC1, BC3, BC4, BC5, BC7, PVRTC1, ASTC 4x4 (and all other ASTC block sizes for ASTC/XUASTC sources), ATC, FXT1, EAC R11/RG11, BC6H, ASTC HDR, and uncompressed RGBA32, RGB565, RGBA4444, half float and RGB9E5.
- **JS/WASM build** ([`webgl/transcoder/CMakeLists.txt`][bu-js]). Emscripten with embind (`--bind`), `MODULARIZE=1`, `EXPORT_NAME=BASIS`, `ALLOW_MEMORY_GROWTH=1`, KTX2 and Zstandard on, ATC, FXT1, PVRTC2 and EAC RG11 off. It is **not** built with `-sDYNAMIC_EXECUTION=0`, so embind builds its invoker functions with the `Function` constructor at start-up (section 4 and the measurement in section 6). The output is a classic script that defines a global `BASIS`.
- **Pure C API for WASI** ([`basisu_wasm_transcoder_api.h`][bu-capi]). Since v2.x there is also a C ABI (`bt_init`, `bt_alloc`, `bt_free`, `bt_ktx2_open`, `bt_ktx2_get_*`, `bt_ktx2_transcode_image_level`, …) compiled to a WASI module with no JavaScript glue. The prebuilt `basisu_transcoder_module_st.wasm` imports only seven `wasi_snapshot_preview1` functions (`args_get`, `args_sizes_get`, `fd_close`, `fd_fdstat_get`, `fd_seek`, `fd_write`, `proc_exit`), which a worker can stub. It contains every codec and is 2.35 MB (794 KB gzip); a build restricted to ETC1S and UASTC LDR would be much smaller (section 7).
- **Encoder.** `basisu` (C++ CLI, also built to WASI and to a JS encoder) encodes PNG, JPEG, QOI, TGA, DDS and EXR to `.ktx2` with `-etc1s`/`-uastc`, `-mipmap`, `-q`/`-quality`, `-uastc_rdo_l` and `-ktx2_zstandard_level`. This is what a data pipeline (M9) would run.

### KTX-Software (Khronos KTX2 tools and libktx)

- **Tools.** v5 replaced the legacy `toktx` family with one `ktx` suite: `create`, `encode` (Basis ETC1S/UASTC, ASTC, UASTC HDR), `transcode`, `deflate` (Zstandard or zlib supercompression), `extract`, `validate`, `compare` (PSNR/SSIM), `info`, `convert`, `patch` ([`tools/ktx/`][ks-tools]). v5 adds UASTC HDR encoding and transcode targets; `ktx validate` checks files against the KTX 2.0 specification.
- **libktx JS bindings** ([`CMakeLists.txt`][ks-cmake]). Emscripten embind builds `libktx.js` and `libktx_read.js` with `GL_PREINITIALIZED_CONTEXT=1`. `ktx.texture.transcodeBasis(target, flags)` transcodes, and `glUpload()` uploads straight into the page's **WebGL** context through Emscripten's GL layer ([`ktx_wrapper.cpp`][ks-js]). This path is main-thread, WebGL-only and does not fit a worker or WebGPU.
- **`msc_basis_transcoder`.** A standalone transcoder build (`EXPORT_NAME=MSC_TRANSCODER`) that Babylon.js still uses for ETC1S. Its maintainers propose removing it now that Basis Universal reads KTX2 itself ([KTX-Software #377][ks-377]).

### Draco

- **Codec.** Mesh and point-cloud compression with quantization, prediction and an Edgebreaker connectivity coder. In glTF it is `KHR_draco_mesh_compression`; in 3D Tiles 1.0 point clouds it is `3DTILES_draco_point_compression`.
- **JS/WASM build** ([`draco_emscripten.cmake`][dr-em]). Emscripten with a WebIDL binder (not embind), `MODULARIZE=1`, `ALLOW_MEMORY_GROWTH=1`, `FILESYSTEM=0`, exported heap views. The glTF-only decoder is 184 KB of WASM (60 KB gzip) plus a 55 KB wrapper (13 KB gzip). The wrapper is a classic script exposing `DracoDecoderModule`. A search of the prebuilt glTF wrapper (in Draco and in three.js's copy) for the `Function` constructor and `eval` found none.
- **Loading guidance.** The project recommends loading decoders from `https://www.gstatic.com/draco/versioned/decoders/<version>/` so that sites share a cached copy ([`time_draco_decode.html`][dr-time]). VibeGlobe's same-origin rule forbids this.

### meshoptimizer

- **Codec.** Vertex and index buffer codecs designed to be decoded at GPU-upload speed, with optional filters (octahedral normals, quaternions, exponential, color) applied after decoding. In glTF it is `EXT_meshopt_compression` and the newer `KHR_meshopt_compression`. Output is a byte-exact buffer ready for the GPU; quantization (the only lossy step) happens before encoding, typically in gltfpack.
- **JS decoder** ([`meshopt_decoder.mjs`][mo-dec]). One ES module, 7.7 KB gzip, with the WebAssembly embedded as a packed string (a SIMD build and a scalar build; a 51-byte probe module picks one with `WebAssembly.validate`). It instantiates from bytes, so it needs `'wasm-unsafe-eval'` but no network request. `decodeVertexBuffer`, `decodeIndexBuffer`, `decodeIndexSequence` and `decodeGltfBuffer` are **synchronous** after `ready` resolves. The optional `useWorkers(n)` builds its workers from a **Blob URL** of concatenated function sources, which a strict CSP rejects; it is not needed when the caller is already a worker.
- **Memory.** WebAssembly memory grows with the largest decoded buffer and never shrinks ([meshoptimizer #522][mo-522]).

### CesiumJS

- **KTX2 transcoding.** [`KTX2Transcoder`][ce-ktx2] owns one `TaskProcessor("transcodeKTX2")` with unlimited active tasks ("KTX2 transcoding is used in place of `Resource.fetchImage`, so it can't reject"). The worker [`transcodeKTX2.js`][ce-tw] parses the container with `ktx-parse`, rejects arrays and 3D textures, and transcodes with the Basis embind module (`ThirdParty/basis_transcoder.wasm`, fetched on the main thread and handed to the worker). Other KTX2 files are read as uncompressed data: RGB for `VK_FORMAT_R8G8B8_SRGB`, RGBA otherwise, with 8-bit, half-float or float components.
- **Target order.** ETC1S: ETC2 → ETC1 (opaque only) → S3TC (BC1/BC3) → PVRTC → ASTC → BC7. UASTC: ASTC → BC7 → S3TC → ETC2 → ETC1 → PVRTC. No uncompressed fallback: with no supported target the load fails.
- **Capability detection.** [`Context.js`][ce-ctx] reads the WebGL extensions and passes them to `loadKTX2.setKTX2SupportedFormats` "because imagery layers don't have access to the context". **The ETC2 lookup asks for `"WEBG_compressed_texture_etc"`** (missing `L`), so ETC2 is never detected and ETC1S files on ETC2-only devices fall through to ETC1 or ASTC, or fail when they have alpha. The issue search found no report of it. The transcoding specs inject the supported formats directly, so the typo is never exercised by a test.
- **Upload and memory.** [`Texture.js`][ce-tex] uploads level 0 and then each `mipLevels` entry with `compressedTexImage2D`. `sizeInBytes` comes from [`PixelFormat.compressedTextureSizeInBytes`][ce-pf] for level 0 only; the 4/3 factor is applied only after `generateMipmap()`, which compressed textures cannot call, so **compressed mip levels are not counted**.
- **Imagery.** [`ImageryProvider.loadImage`][ce-ip] routes URLs ending in `.ktx2` to `loadKTX2`. [`ImageryLayer`][ce-il] builds the texture from a single `arrayBufferView`, and `_finalizeReprojectTexture` enables mipmaps only for non-compressed power-of-two textures, so **compressed imagery tiles are sampled without mipmaps**.
- **Draco.** [`decodeDraco.js`][ce-draco] runs in a worker. With `dequantizeInShader` it calls `SkipAttributeTransform` so positions and normals stay quantized integers on the GPU and are dequantized in the vertex shader, saving vertex memory.
- **meshopt.** glTF buffer views are decoded **synchronously on the main thread** with `MeshoptDecoder.decodeGltfBuffer` ([`GltfBufferViewLoader.js`][ce-gbv]). Cesium's 3D Tiles terrain format is glTF with `EXT_meshopt_compression`, decoded in the terrain worker ([`Cesium3DTilesTerrainGeometryProcessor.js`][ce-3dterrain]). `KHR_meshopt_compression` support was added in 1.143 ([`CHANGES.md`][ce-changes]).

### three.js r186 (the renderer base)

- **`KTX2Loader`** ([`KTX2Loader.js`][th-ktx2]):
  - **Capabilities.** On WebGPU, `detectSupport(renderer)` reads `renderer.hasFeature('texture-compression-astc' | '-etc2' | '-bc')`. The legacy names `texture-compression-s3tc` and `-etc1` are mapped to real WebGPU features by `GPUFeatureMap` ([`WebGPUConstants.js`][th-const]; fixed after [three.js #29745][th-29745]). On WebGL it reads the extensions and, on desktop Linux, disables ASTC and ETC when BC is also exposed, because Mesa drivers "expose ETC1, ETC2 and ASTC even though the hardware doesn't support these" and decompress them in software on the main thread. ASTC HDR is never used on WebGPU.
  - **Target order.** ETC1S: ETC2 → ETC1 → BC7 → BC1/BC3 → PVRTC → RGBA32. UASTC: ASTC 4x4 → BC7 → ETC2 → ETC1 → BC1/BC3 → PVRTC → RGBA32. UASTC HDR: BC6H → RGBA16F. Alpha excludes targets without alpha ([three.js #22899][th-22899]); PVRTC requires power-of-two sizes.
  - **Worker.** `init()` downloads `basis_transcoder.js` and `.wasm`, concatenates the transcoder script with `KTX2Loader.BasisWorker.toString()` into a **Blob URL** worker, and posts a copy of the WASM bytes to each worker. A FIFO `WorkerPool` with `workerLimit` 4 runs the tasks. A second loader instance logs a warning because it loads its own transcoder and workers.
  - **Transcoding.** Per face, level and layer: `getImageTranscodedSizeInBytes`, then `transcodeImage` into a new `Uint8Array`; layers of one level are concatenated; every level buffer is transferred back. Non-multiple-of-four sizes log a warning; textures without mips use the padded size ([three.js #25908][th-25908]).
  - **Non-Basis KTX2.** `createRawTexture` handles raw BCn, ETC2/EAC, ASTC, PVRTC and uncompressed `vkFormat`s, with Zstandard decoded by `zstddec` on the calling thread.
  - **Result.** `CompressedTexture` (or `CompressedArrayTexture`, `CompressedCubeTexture`) with `generateMipmaps = false`, `minFilter` mipmapped only if the file has several levels, and color space from the data format descriptor.
- **Upload on WebGPU** ([`WebGPUTextureUtils.js`][th-wgpu-tex]). `getFormat` maps three.js formats plus `colorSpace` to the `-srgb` or linear GPU format. Compressed textures get no `RENDER_ATTACHMENT` usage. `_copyCompressedBufferToTexture` calls `queue.writeTexture` once per level (and per array layer), with `bytesPerRow = ceil(width / blockWidth) × bytesPerBlock` from `_getBlockData` and the extent rounded up to whole blocks, so 2 × 2 and 1 × 1 levels upload correctly. For `CompressedArrayTexture`, `layerUpdates` limits the upload to the changed layers. `mipLevelCount` is `mipmaps.length`, forced to 1 when a compressed texture has no mipmaps ([`Textures.js`][th-textures]).
- **Upload on the WebGL2 fallback** ([`WebGLTextureUtils.js`][th-wgl-tex]). `texStorage2D`/`texStorage3D` with the level count, then `compressedTexSubImage2D` per level, or `compressedTexSubImage3D` per changed layer for arrays. sRGB BC1–BC3 need `WEBGL_compressed_texture_s3tc_srgb`; without it `WebGLUtils.convert` returns `null` and the upload is skipped with a warning ([`WebGLUtils.js`][th-wgl-utils]).
- **Memory accounting.** `Info._getTextureMemorySize` returns **1** for every compressed texture ("Fallback estimate since exact format decompressed isn't readily available") in r186 and still on `dev` ([`Info.js`][th-info]). `info.memory.texturesSize` therefore cannot verify compressed bytes. `TextureUtils.getByteLength(width, height, format, type)` does compute block sizes for BC, ETC2/EAC, ASTC (all block sizes), BPTC and PVRTC ([`TextureUtils.js`][th-tu]).
- **`DRACOLoader`** ([`DRACOLoader.js`][th-draco]). The same Blob-URL worker construction, `workerLimit` 4, and tasks assigned to the worker with the lowest summed byte cost. The decoder path must be set by the application; making gstatic the default was declined ([three.js #27263][th-27263]). Results are cached per input buffer so a buffer is never transferred twice.
- **meshopt.** `GLTFLoader.setMeshoptDecoder` accepts the vendored `meshopt_decoder.module.js` (meshoptimizer 1.1 in r186) for `EXT_meshopt_compression` and `KHR_meshopt_compression` ([`GLTFLoader.js`][th-gltf]).
- **Fit with ADR 0011.** Neither loader can be used as is: both build Blob-URL workers, keep their own pools and fetch through `FileLoader`, and the bundled Basis transcoder needs `'unsafe-eval'`.

### Babylon.js

- **Two-part KTX2 path.** [`KhronosTextureContainer2`][ba-ktx2] (core) owns a worker pool and the upload; the separate `ktx2Decoder` package parses KTX2 and picks a transcoder.
- **Worker and loading.** By default it uses half the logical processors, capped at 4 workers, built from a **Blob URL** of the stringified worker function. Every decoder URL defaults to `https://cdn.babylonjs.com/…` (`babylon.ktx2Decoder.js`, `ktx2Transcoders/1/uastc_astc.wasm`, `msc_basis_transcoder.js`, `zstddec.wasm`, …) and can be overridden through `URLConfig`. Without workers, the decoder runs on the main thread.
- **Transcoders.** UASTC goes through small "lite" WebAssembly modules, one per target pair (UASTC→ASTC, UASTC→BC7, UASTC→RGBA8 sRGB or linear, UASTC→R8, UASTC→RG8), instantiated with `WebAssembly.instantiate` and a shared imported `WebAssembly.Memory`, with no JS glue ([`liteTranscoder.ts`][ba-lite]). They come from Khronos' Basis-Universal-Transcoders, archived on 2026-07-13, which never implemented ETC1S. ETC1S therefore goes through KTX-Software's embind `msc_basis_transcoder` ([`mscTranscoder.ts`][ba-msc]).
- **Target order** ([`transcodeDecisionTree.ts`][ba-tree]). ETC1S: ETC2 → ETC1 → BC7 → BC1/BC3 → PVRTC → RGBA32. UASTC: ASTC → BC7 → (option: RGBA32) → ETC2 → ETC1 → BC1/BC3 → PVRTC → RGBA32. Options force RGBA, R8 or RG8 for non-color data ([Babylon.js #8982][ba-8982]).
- **Upload.** `_uploadCompressedDataToTextureDirectly` per level. On WebGPU, [`webgpuTextureManager.updateTexture`][ba-wgpu] uses a mapped staging buffer and `copyBufferToTexture` when `bytesPerRow` is a multiple of 256, and `queue.writeTexture` otherwise. On WebGPU, `s3tc` and `bptc` both come from `texture-compression-bc`, and `etc1` is never reported. The KTX2 upload path rejects array textures.
- **Draco and meshopt.** [`dracoCodec.ts`][ba-draco] builds a Blob-URL worker pool (half the processors, capped at 4) and defaults to `https://cdn.babylonjs.com/draco_wasm_wrapper_gltf.js` with an asm.js fallback; `numWorkers = 0` decodes on the main thread. meshopt defaults to the Babylon CDN copy of `meshopt_decoder.js`.

### loaders.gl

- **Basis.** [`basis-module-loader.ts`][lg-bml] loads `basis_transcoder.js` and `.wasm` through `loadLibrary` (CDN by default, overridable, or injected through `options.modules`). [`parse-basis.ts`][lg-pb] wraps every transcode in `withBasisTranscodingLock`, because the transcoder module is not re-entrant, and handles Basis and KTX2 including arrays and cube faces.
- **Target selection** ([`basis-format-utils.ts`][lg-bfu]) uses WebGPU texture-format names (`bc7-rgba-unorm`, `etc2-rgba8unorm`, `astc-4x4-unorm`, …) as the vocabulary for both APIs. ETC1S: ETC2 → ETC1 → BC7 → BC1/BC3 → PVRTC → ATC → RGBA32. UASTC: ASTC 4x4 → BC7 → BC1/BC3 → ETC2 → ETC1 → PVRTC → ATC. XUASTC/ASTC LDR: the matching ASTC block size, else BC7, BC, ETC2. HDR: ASTC HDR, BC6H, RGBA16F. Results carry both the GL constant and the WebGPU format name; uploading is left to luma.gl.
- **Draco.** [`draco-module-loader.ts`][lg-dml] defaults to gstatic for the decoder and jsDelivr for the encoder; the worker bundle defaults to unpkg. Local overrides through `options.modules` were broken until a 2026 fix ([loaders.gl #3185][lg-3185]).
- **meshopt.** The glTF module vendors `meshopt-decoder.mjs` and applies `EXT_meshopt_compression`/`KHR_meshopt_compression` while parsing.

### 3DTilesRendererJS

- **Delegation.** [`GLTFExtensionsPlugin`][tt-gltf] hands three.js `DRACOLoader`, `KTX2Loader` and a meshopt decoder to `GLTFLoader`, and registers the Draco loader for `.drc` so [`PNTSLoader`][tt-pnts] can decode `3DTILES_draco_point_compression`. Without these the tiles fail or render untextured ([3DTilesRendererJS #307][tt-307], [#733][tt-733]).
- **Google Photorealistic 3D Tiles** examples register only a Draco decoder ([`googleMapsAerial.js`][tt-google]), so that data set needs Draco.
- **Memory after decoding.** [`TileCompressionPlugin`][tt-tcp] re-quantizes decoded geometry on the main thread: indices to the smallest integer type, optional int8 normals and UVs, and int16 positions normalized to the bounding box with the mesh scale and position adjusted. It also turns mipmaps off, on the argument that the tile hierarchy already provides levels of detail ([#614][tt-614]).
- **Byte accounting.** [`MemoryUtils.getTextureByteLength`][tt-mem] sums `mipmaps[i].data.byteLength` for compressed textures and falls back to `TextureUtils.getByteLength`; uncompressed textures get × 4/3 when mipmaps are generated.

## 5. How they test and benchmark compression

- **Basis Universal.** The `basisu` tool has built-in self-tests (`-test`, `-test_hdr_4x4`, `-test_hdr_6x6`, `-test_xuastc_ldr`, and since v2.5 `-test_codecs`, which runs every codec "in various ways") that encode, transcode and check quality. `-compare` and `-stats` print PSNR per channel. AppVeyor builds the tool on Linux and Windows. There are no browser tests of the WASM transcoder.
- **KTX-Software.** GoogleTest suites for textures, transcoding, streams and threads (`tests/{texturetests,transcodetests,streamtests,threadtests}`), the KTX-Software-CTS conformance suite for the `ktx` tools (a submodule), a determinism workflow that checks encoder output is byte-identical across platforms and compilers ([`check-determinism.yml`][ks-det]), and manual WebGL test pages (`tests/webgl`).
- **Draco.** 78 GoogleTest files (`*_test.cc`) run in a CI matrix of build types, and four libFuzzer targets for the mesh and point-cloud decoders, with and without dequantization (`src/draco/tools/fuzz`). The JS build is timed only by a manual page, `time_draco_decode.html`.
- **meshoptimizer.** `make test` in sanitize, debug, release and coverage configurations (including a scalar-only coverage run), `node js/meshopt_decoder.test.js` in CI with hand-written encoded buffers and expected bytes, a codec fuzzer run through CIFuzz, `codecbench.cpp` and `js/benchmark.js` (throughput in GB/s for vertex, index and filtered glTF decoding).
- **CesiumJS.** Jasmine specs in browsers: [`loadKTX2Spec.js`][ce-spec] transcodes ETC1S and UASTC fixtures to every target by **injecting** the supported-format flags, and checks mip levels, invalid buffers and unsupported 3D textures; `GltfDracoLoaderSpec` and `GltfTextureLoaderSpec` cover the loaders. Capability detection itself is not tested, which is how the ETC2 typo survives. No compression benchmarks.
- **three.js.** No unit tests for `KTX2Loader` or `DRACOLoader` (`test/unit/addons/loaders` covers other loaders). The Puppeteer end-to-end run screenshots every example not on its exception list, which includes `webgl_loader_texture_ktx2`, `webgpu_loader_texture_ktx2`, `webgl_loader_draco`, `webgl_loader_gltf_compressed`, `webgpu_loader_gltf_compressed` and `webgl_texture2darray_compressed` ([`puppeteer.js`][th-e2e]). The headless GPU decides which target path those screenshots exercise.
- **Babylon.js.** Vitest unit tests of the KTX2 decoder (uncompressed arrays, Zstandard levels with odd offsets, rejected inputs) and of the Draco configuration ([`ktx2Decoder.test.ts`][ba-ktx2-test]). Visualization (screenshot) tests for "KTX2 decoder test", "Loading glTF model with KTX2 textures", "Basis loader", Draco with `numWorkers` 0 and 1 and the asm.js fallback, a Draco encoder round trip and a meshopt-compressed glTF ([`config.json`][ba-vis]).
- **loaders.gl.** Vitest specs for `BasisLoader` with `worker: false` and `true`, automatic target selection from a supplied format list, explicit targets, injected modules, and serialization of concurrent transcodes ([`basis-loader.spec.ts`][lg-bspec]); Draco specs for module-loader URLs, worker loading in the browser and writer round trips. probe.gl benchmarks **warm the worker first** and report points per second, sequential and parallel ([`draco.bench.ts`][lg-bench]).
- **3DTilesRendererJS.** No compression tests; it relies on three.js.

Nobody tests the transcoder under a strict CSP, nobody tests capability detection against real extension or feature names, and nobody measures what compressed textures change in GPU memory, upload time or frame time while streaming. VibeGlobe adds all three (section 7).

**Upload** (median of 15; `queue.writeTexture` per level then `onSubmittedWorkDone`; WebGL2 `texSubImage2D`/`compressedTexSubImage2D` per level then `finish`; full chains supplied from the CPU, so the RGBA8 numbers exclude mipmap generation):

| Tile   | WebGPU RGBA8 | WebGPU BC7 | WebGL2 RGBA8 | WebGL2 BC7 |

What the numbers say:

- **ETC1S** is the format for imagery: about the size of WebP, transcoding faster than JPEG decoding, 4–8× less GPU memory, no mipmap generation. It costs 4–5 dB of PSNR against JPEG q85 at the same size, which is visible on photographs.
- **UASTC** matches JPEG quality but is 3.5–4.5× larger, and Zstandard dominates its transcode time. It suits sources where quality matters more than bandwidth (for example hosted orthophotos on a LAN), not general streaming.
- Transcoding is a worker cost of the same order as image decoding, so the ADR 0011 pool sizing holds.

## 7. Approach chosen and why

Recorded in [ADR 0020](../adr/0020-texture-and-geometry-compression.md). In short:

**1. What is compressed, and when.**

- **Imagery sources keep their formats.** JPEG, PNG and WebP tiles stay on the ADR 0010 §6 path: decoded in a worker to `ImageBitmap` (`premultiplyAlpha: 'none'`, `colorSpaceConversion: 'none'`), uploaded as RGBA8 with GPU-generated mipmaps. This is the fallback F104 asks for, and the only path for providers that do not offer KTX2.
- **KTX2 sources** (declared by the source, or detected from `image/ktx2` or the `«KTX 20»` magic) are transcoded in workers to the best block format the device has. ETC1S and UASTC LDR 4x4 (`vkFormat = 0`, Basis supercompression) are supported in M3. KTX2 files that already hold BC1–BC7, ETC2 or ASTC 4x4 without supercompression are passed through when the device supports that format. Zstandard-supercompressed raw formats, XUASTC, XUBC7 and HDR wait for a measured need (section 8).
- **Requirements on KTX2 tiles**, checked when the source is created and on every tile: base size a multiple of 4, a full mip chain, 2D only. A tile that breaks them is transcoded to RGBA32 and gets GPU mipmaps, with a one-time warning per source. Compressed tiles are never sampled without mipmaps (unlike CesiumJS imagery).
- **No real-time encoding** of JPEG tiles to BC1/ETC2 in M3; it is an open question with a measurement plan.

**2. Target formats per backend.** One pure function in `core` maps (source codec, alpha, color or non-color data, capabilities) to a target, unit-tested for every combination:

| Source            | Desktop class (BC available) | Mobile class (no BC; ETC2 and/or ASTC)                 | Nothing compressed |
| ----------------- | ---------------------------- | ------------------------------------------------------ | ------------------ |
| ETC1S, opaque     | BC1 (0.5 B/px)               | ETC2 RGB (0.5 B/px), else ASTC 4x4                     | RGBA8              |
| ETC1S, alpha      | BC7                          | ETC2 RGBA, else ASTC 4x4                               | RGBA8              |
| UASTC (color)     | BC7                          | ASTC 4x4, else ETC2 RGBA/RGB                           | RGBA8              |
| UASTC (non-color) | BC7                          | ASTC 4x4, else **RGBA8** ([Babylon.js #8982][ba-8982]) | RGBA8              |

- **WebGPU.** Capabilities come from `device.features`: `texture-compression-bc` (BC1–BC7), `texture-compression-etc2` (ETC2/EAC), `texture-compression-astc`. three.js r186 already requests every compression feature the adapter offers (`WebGPUBackend` puts all supported `GPUFeatureName`s in `requiredFeatures`), and `capabilities.ts` already reads them. Formats are the `-srgb` variants for imagery (`bc1-rgba-unorm-srgb`, `bc7-rgba-unorm-srgb`, `etc2-rgb8unorm-srgb`, `etc2-rgba8unorm-srgb`, `astc-4x4-unorm-srgb`) and the linear ones for data.
- **WebGL2.** `WEBGL_compressed_texture_s3tc` plus `WEBGL_compressed_texture_s3tc_srgb` for BC1/BC3 (BC1 is used for sRGB imagery only when the sRGB extension exists; otherwise BC7), `EXT_texture_compression_bptc` for BC7, `WEBGL_compressed_texture_etc` for ETC2/EAC, `WEBGL_compressed_texture_astc` (LDR profile) for ASTC.
- **BC first whenever BC exists**, on both backends, because drivers can expose emulated ETC2 and ASTC on desktop (three.js's Mesa comment, [#29745][th-29745]); ETC2 and ASTC are chosen only on devices without BC, even where UASTC → ASTC would be a closer transcode (revisited by open question 3). ETC1 and PVRTC are not targets. ETC1 blocks are valid ETC2 RGB blocks, so ETC2 covers every device that can use them (a device exposing only `WEBGL_compressed_texture_etc1` gets RGBA8); PVRTC needs power-of-two sizes and has the lowest quality.
- **Detection is tested against real names.** A unit test lists the exact WebGPU feature names and WebGL extension names the engine queries and compares them with the WebGPU and WebGL registries' spelling (CesiumJS's `WEBG_` typo). An end-to-end test forces each target in turn (a debug option, `?compressedTarget=`) on SwiftShader, which exposes all of them on both backends (section 6).
- The chosen target per source is fixed when the source is attached (capabilities do not change without a device loss), so byte predictions are exact.

**3. Transcoder: our own build of the Basis Universal transcoder.**

- **Code:** the upstream C++ transcoder (Apache-2.0), pinned to an exact commit, compiled to WebAssembly **without Emscripten's JS glue**: a small C ABI (open, level info, transcode level, alloc/free) built with clang/wasi-sdk, with the WASI imports the worker stubs. This removes embind and its `Function`-generated invokers, so the worker needs only `'wasm-unsafe-eval'`. Basis's own `basisu_wasm_transcoder_api` shows the approach works: its prebuilt module imports only seven trivial WASI functions. The fallback, if the C ABI build fails a criterion below, is the embind build relinked with `-sDYNAMIC_EXECUTION=0 -sEXPORT_ES6=1 -sENVIRONMENT=worker`, which [three.js #34389][th-34389] reports works.
- **Contents:** ETC1S and UASTC LDR 4x4 decoders, Zstandard decompression, and the targets BC1, BC3, BC4, BC5, BC7, ETC2 RGB/RGBA, EAC R11/RG11, ASTC 4x4 and RGBA32. Everything else is compiled out (`BASISD_SUPPORT_*` flags). Target: at most 150 KB gzip, checked by `npm run size`.
- **Delivery:** a content-hashed file next to the worker program, resolved from `assets.wasmBaseUrl` (ADR 0011), fetched and compiled with `WebAssembly.compileStreaming` by each worker on its **first** KTX2 task, so apps that never use KTX2 never download it. It is outside the 100 KB worker budget as lazily loaded WebAssembly. The built `.wasm`, its build script and the pinned toolchain version are committed; a nightly job rebuilds it and compares hashes. Its license goes into `THIRD_PARTY_NOTICES.md`.
- **Container parsing:** a small original TypeScript KTX2 reader in the worker reads the header, level index and data format descriptor (color model, transfer function, alpha) to validate the file and predict bytes before any WebAssembly runs. It is fuzzed like every task (ADR 0011).
- **Failure:** if compilation is refused (CSP) or the transcoder fails to start, KTX2 sources report a typed `format-unsupported` error naming the cause; there is no JS transcoder fallback. Malformed files fail the tile with a typed error; the ADR 0011 watchdog covers hangs.

**4. Where transcoding runs.** In the ADR 0011 worker pool, as a pure task `transcodeKtx2(bytes, target) → { format, width, height, levels: ArrayBuffer[] }`. All levels of one tile are transcoded in one task (the Basis note on Zstandard levels, [basis_universal #203][bu-203]). One transcoder instance per worker, one task at a time, so no lock is needed. Level buffers are transferred. Input bytes are a copy of the RAM-tier entry, because the tier keeps the encoded file for loss recovery ([three.js #24806][th-24806]). The transcoder's WASM memory is capped (initially 64 MB); above the cap the worker drops and re-instantiates the module.

**5. Upload within the frame budget.**

- The renderer builds a three.js `CompressedTexture` from the transferred levels (`generateMipmaps = false`, `flipY = false`, `colorSpace` from the KTX2 transfer function) and uploads it with `renderer.initTexture()` from the ADR 0007 queue, exactly like image tiles. r186 writes each level with `queue.writeTexture` on WebGPU and `compressedTexSubImage2D` after `texStorage2D` on WebGL2.
- The cost model keeps a separate bytes-per-millisecond average per (backend, compressed or uncompressed), because uncompressed uploads also pay a GPU mipmap pass and compressed ones do not.
- A 512 px BC7 tile with mips is 350 KB, far below the 8 MB slice limit, so tiles are never sliced; the whole chain uploads in one frame, so a tile is never sampled with missing levels. Slicing by mip level stays reserved for large glTF textures (M10, M13).
- One immutable GPU texture per tile ([three.js #29786][th-29786]). Texture pages (ADR 0010 rule 7), if adopted, use one array texture per format; r186 supports per-layer compressed uploads on both backends (`layerUpdates`), but compressed arrays need a device test first ([three.js #29539][th-29539]).

**6. Byte accounting.**

- ADR 0007's "texels × bytes per texel × 4/3" applies to uncompressed textures only. Compressed textures count exactly the sum, over levels, of `ceil(w / blockWidth) × ceil(h / blockHeight) × bytesPerBlock`, which equals the sum of the transferred level byte lengths. Both are computed and must agree (debug assertion).
- The prediction at dispatch is exact: tile size, level count and target are known from the source and the device.
- three.js's `info.memory.texturesSize` counts compressed textures as 1 byte in r186 ([`Info.js`][th-info]), so ADR 0010 §6's cross-check against it is replaced, for compressed textures, by a test-time cross-check against `TextureUtils.getByteLength` per level. The engine's own counters are the source of truth for budgets and the debug overlay, which shows GPU bytes per format family.
- RAM tier: encoded KTX2 bytes, as for any tile. Transcoded levels are transient and released after upload.

**7. Geometry compression.**

- **Terrain (M4 onward): none needed.** Terrain meshes are built by the engine in workers from height grids (ADR 0006, ADR 0013), so there is nothing compressed to download beyond each terrain format's own encoding (quantized-mesh's zigzag-delta vertices and high-water-mark indices, Terrarium/Terrain-RGB PNG or WebP), which the sources survey (M7) covers. Smaller vertex formats for engine-built tiles (normalized int16 offsets, as in 3DTilesRendererJS's `TileCompressionPlugin` and CesiumJS's `dequantizeInShader`) are a memory option for M4 to measure, not a compression codec.
- **glTF models (M10) and 3D Tiles (M13): both decoders.** `KHR_draco_mesh_compression` is required by real data (Google Photorealistic 3D Tiles), and `EXT_meshopt_compression`/`KHR_meshopt_compression` by gltfpack output, Cesium ion assets and Cesium's 3D Tiles terrain. Both decode in the worker pool as tasks producing flat typed arrays, never on the main thread (unlike CesiumJS's synchronous meshopt path):
  - **meshopt:** the upstream ES module decoder (MIT), pinned, imported lazily by the worker; its synchronous API is used directly and `useWorkers` never (Blob workers).
  - **Draco:** the upstream glTF decoder (Apache-2.0) rebuilt as an ES module (`-sEXPORT_ES6=1 -sENVIRONMENT=worker -sDYNAMIC_EXECUTION=0`), pinned, lazily loaded from `assets.wasmBaseUrl`. Counts in the bitstream are validated against the buffer size before decoding ([Draco #1169][dr-1169]); output array types follow the declared quantization bits ([CesiumJS #10977][ce-10977]); WASM memory is capped as for the transcoder.
- **VibeGlobe's own pipeline (M9)** emits meshopt, not Draco, when it produces meshes: its decoder is 8 KB instead of about 75 KB, decodes at over 1 GB/s, and output is byte-exact GPU data.

**9. Verification (M3, F104).**

- **Fixtures:** KTX2 imagery tiles (ETC1S and UASTC, opaque and alpha, with and without mips, non-multiple-of-4, truncated and corrupt) generated by a pinned `basisu` from the playground's PNG fixtures, with recorded hashes and PSNR.
- **Unit tests (Node):** target selection for every capability combination; the KTX2 reader; the transcoder task in Node's WebAssembly against golden level hashes and PSNR thresholds per target; byte accounting against `TextureUtils.getByteLength`; fuzzing of the reader and the task.
- **End-to-end (Playwright, both backends):** a KTX2 fixture source renders each forced target and the RGBA8 fallback, compared to the JPEG source by screenshot within the ADR 0012 thresholds; GPU bytes per tile drop by the expected factor (4× for BC7, 8× for BC1); the strict-CSP run with `'wasm-unsafe-eval'` only in the worker loads KTX2 tiles; an app that never uses KTX2 never requests the transcoder; the upload budget per frame holds during a flight over a KTX2 source.
- **Benchmarks (`npm run bench`):** transcode time per target and tile size with warmed workers, upload time per tile and format, and p95 frame time and GPU bytes during the standard flight with a KTX2 source versus the JPEG source, on the reference devices. F104's memory and upload-time numbers go into ADR 0020.
- **Soak:** worker heap and WASM memory flat over 10,000 transcodes.

## 8. Open questions

1. **Real-time encoding of JPEG/WebP tiles to BC1 or ETC2 in workers.** It would bring the 8× memory saving to every imagery provider, at the cost of CPU time and quality. Measure a fast BC1 encoder's time and PSNR per 256 px tile in M3 or M4; adopt only if GPU memory, not bandwidth, limits the working set on the reference mobile device.
2. **ETC1S → BC1 versus BC7 on desktop.** BC1 halves memory; BC7 may preserve ETC1S quality slightly better. Measure PSNR of both on the fixtures in M3 and keep BC1 unless the difference exceeds 0.5 dB.
3. **Do WebGPU implementations ever expose emulated ETC2 or ASTC on desktop?** three.js applies its emulation heuristic only on WebGL. Check on the reference Linux, Windows and macOS machines. If none does, WebGPU devices that expose both BC and ASTC (Apple silicon) could take UASTC → ASTC 4x4, the closer transcode, instead of BC7; until then "BC first" holds everywhere.
4. **Transcoder size.** If the C ABI build exceeds 150 KB gzip, drop targets (EAC, BC4/BC5) that imagery does not need until data layers do.
5. **Zstandard-supercompressed raw formats and XUASTC/XUBC7.** Support only when a real source uses them; the data pipeline survey (M9) decides what VibeGlobe's own tools emit.
6. **Sharing compiled WebAssembly across workers.** Each worker compiles the module (97 ms measured with the 527 KB build). Browsers cache compiled code for streamed compilation of the same URL; measure whether a second worker's start-up is fast enough before considering passing a `WebAssembly.Module` between workers.
7. **Quantized vertex formats for terrain** (int16 offsets in the tile box): precision versus memory, measured in M4 against ADR 0004's error budget.
8. **glTF parsing location** for M10 and M13 (worker-side parsing producing flat buffers versus three.js `GLTFLoader` with worker-backed decoder hooks): decided in the vector and 3D Tiles survey.
