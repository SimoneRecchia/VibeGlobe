# 0015. Owner decisions of 2026-10-20 (open questions 1–12)

- Status: Accepted (license part, item 7, superseded by 0043)
- Date: 2026-10-20
- Milestone: M1 (applies to every milestone)

## Context

M1 left twelve questions that only the owner could answer (`docs/open-questions.md`). The owner answered all of them on 2026-10-20 and replaced `PLAN.md` with a version that already contains the answers. One principle governs several of them: **the project runs no servers**. Every consumer hosts tiles, offline packages and engine assets in their own backend and frontend; the repository provides the tools and documentation to do so.

This ADR records the answers, what each changes in the repository and in later milestones, and the choices made to implement them. Where it changes an earlier ADR, that ADR's status and a dated note point here.

## Options considered

The options for each question are the ones listed in `docs/open-questions.md` before this decision (git history of that file), plus, for the license, the owner's choice between keeping the project private and publishing it as source-available.

## Decision

1. **Name, repository and registry.** VibeGlobe is a public, source-available project; the repository may stay private until the first release (update 2026-10-21: the owner made the repository public that day, ahead of the first release; see the update at the end). It stays under the owner's personal account, renamed to `SimoneRecchia/VibeGlobe`. Packages are published on the public npm registry under the npm organization `vibeglobe`, which the owner created: `@vibeglobe/core`, `@vibeglobe/vue` and so on (the scope chosen in M1 is kept).
   - The project was renamed from VibeGlobeEngine to VibeGlobe everywhere except git history: package metadata (the root package is `vibeglobe`), README, `CLAUDE.md`, documentation, ADRs and research surveys, code identifiers (`vge` prefixes became `vibeglobe`: `window.vibeglobePlayground`, `.vibeglobe-debug-overlay`, and the `vibeglobe:frame` measure that ADR 0012 names) and the `VGE_` environment-variable prefix, now `VIBEGLOBE_` (`VIBEGLOBE_CHROMIUM_PATH`, `VIBEGLOBE_DEVICE`, `VIBEGLOBE_HW`, `VIBEGLOBE_FC_SEED`, `VIBEGLOBE_FC_RUNS`) in `init.sh`, the Playwright configuration, the benchmark runner and CI. The Web Component tag `<vibe-globe>` already matched the new name and is unchanged. The git remote points to `https://github.com/SimoneRecchia/VibeGlobe`.
   - Frozen `feature_list.json` text that names the old project or a private registry is handled by [ADR 0016](0016-superseded-feature-entries.md).
2. **Reference devices.** No paid cloud device service for now; the owner is asked again before M15. The owner's answer listed the fields to provide (desktop: CPU, GPU, operating system, browsers; tablet: model, operating system) without values, so the devices themselves stay an open question; the proposals in `docs/plan/quality.md` remain the working assumption.
3. **Hosting.** No hosted infrastructure, ever. Tests use local fixture servers. A Docker-based static "LAN server" script (M8, F550) lets any machine play the offline local-network role, and a hosting guide (M9, F553) shows consumers how to serve tiles, packages and engine assets themselves.
4. **Sentinel-2 egress.** Full builds are not part of the project. The pipeline is built and tested on small sample areas and ships ready-to-run configurations for the world low-detail and Italy high-detail builds, which consumers run on their own AWS account (F551, F554). Before any download the pipeline prints the estimated size and cost, including requester-pays transfer, and asks for confirmation (F552).
5. **Google Maps Platform.** The owner's billing region is the EEA (Italy), so the Google Maps Platform EEA Terms apply. The owner provides a restricted key as the `GOOGLE_MAPS_API_KEY` environment variable and CI secret; it is never committed. Real-endpoint tests stay within the free monthly caps, stop at the first quota error, and do not run without a key (F549).
   - Implementation choice: the live tests are a separate command (`npm run test:live`, added in M7) that is not part of `npm test` or `npm run test:e2e`. Without a key it prints that the live suite did not run and exits successfully; nothing inside a suite is skipped, so the no-skip lint rule (KB-008) still holds. The fixture conformance suites always run. CI runs the live command only when the secret exists, at most nightly, with a per-run request budget derived from the caps recorded in the Google terms ADR (F256).
6. **CI.** ADR 0012 stays: CI has no GPU and uses SwiftShader. CI saves minutes and uses no paid GPU runners:
   - every push, and every pull request from a fork, runs one **fast job** with every non-browser check: type check, lint, format check, repository checks, dead code, feature-list and test guards, unit tests with coverage, license audit and notices, API documentation, build, consumer check, bundle size and tree shaking. Amended 2026-10-22 at the owner's request: every pull request, from this repository too, runs the fast job; its check run, `Fast checks`, is the status check the branch ruleset requires (a skipped pull-request run reported no check and blocked the merge).
   - pushes to `main`, a **nightly** schedule and manual runs (`workflow_dispatch`, also usable on a branch before merging) add the browser jobs: end-to-end tests and the recorded benchmarks; later milestones add their visual, scenario and live-provider jobs to this full suite;
   - a newer push cancels an older run of the same branch, except on `main`, where every commit gets a full run.
   - One job instead of six saves the per-job runner start-up and minute rounding. The checks named by F027 still run on every push and pull request.
7. **License: PolyForm Noncommercial License 1.0.0** (SPDX `PolyForm-Noncommercial-1.0.0`). Noncommercial use is free; any commercial use, resale included, needs a separate commercial license from the owner.
   - `LICENSE.md` holds the official text from the PolyForm Project's 1.0.0 release, byte for byte, preceded by the owner's `Required Notice:` line; Prettier ignores it. Every `package.json` (root, libraries and apps) declares the identifier, and `npm run check` enforces it.
   - The README has a licensing section with the commercial-license request path. External contributions require the contributor license agreement (`CLA.md`) so they can be offered under both licenses; `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1, CC BY 4.0), issue templates and a pull request template carrying the CLA line were added (F544).
   - **Dependency compatibility.** The license audit allows only MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0 and ISC, plus OFL-1.1 for fonts. Each of these lets a component be redistributed inside a work licensed on other terms, noncommercial or commercial, as long as its own notices travel with it: MIT, BSD and ISC require the copyright and permission notice; Apache-2.0 also requires its license text, any `NOTICE` file and marking of modified files; OFL-1.1 allows bundling fonts with software, sold or not, but not selling the fonts by themselves and not reusing reserved font names for modified fonts. `THIRD_PARTY_NOTICES.md` (generated and checked in CI) carries these notices, and third-party components stay under their own licenses, not PolyForm. Today no third-party package ships (the audit lists 0); three.js (MIT), arriving in M2 (ADR 0010), is compatible. Default map data is not bundled: consumers build it with the pipeline under the data licenses recorded in M9.
   - The CLA was written for this project and still needs the owner's legal review; until then external contributions are not merged (open questions).
8. **Panning in the flat 2D phase:** constant ground scale, as ADR 0008 and ADR 0009 proposed.
9. **Tilt timing:** the phase table is right: a 0° 2D band at region and city scale, with tilt rising only at neighborhood scale; each curve eases in and out at its ends. The new `PLAN.md` wording says so, and F548 replaces F149.
10. **Heading near the poles:** free rotation with no jump, never an automatic north-up (ADR 0009 as is).
11. **Worker and asset hosting:** same-origin only is right (ADR 0011). Consumers serve engine assets from their own origin, offline LAN installs included. The asset base path stays configurable (`assets.workerUrl`, `assets.wasmBaseUrl`); no CDN support is needed now (follow-up list).
12. **Initial-JavaScript budget:** no separate lightweight first-frame path. M2 measures three.js after tree-shaking, makes time to first frame (at most 1 s on a LAN server) the binding target, sets the byte budget from that measurement with a CI size check that blocks regressions (F546), and makes the engine loadable lazily by host apps through a dynamic import (F547). The 300 KB proposal in `docs/plan/quality.md` is withdrawn.

## Consequences

- `PLAN.md` was replaced by the owner's new version. It had only ever been changed by the owner's upload, so no agent clarification needed carrying over.
- Nine feature-list entries that can no longer pass are `superseded` and twenty new entries carry the new requirements ([ADR 0016](0016-superseded-feature-entries.md), `docs/feature-changes.md`). M1 gained four entries (F542–F545) for the rename, the license, the contributor documents and the CI cadence.
- ADR 0002, 0003, 0008, 0009, 0010, 0011 and 0012 carry a dated note pointing here or to ADR 0016; `docs/plan/` follows this ADR.
- Open owner items now: the reference-device details (question 2), legal review of the CLA, a contact address for commercial licenses, security and conduct reports, the `GOOGLE_MAPS_API_KEY` secret (M7) and an npm token for the `vibeglobe` organization (M15). They are listed in `docs/open-questions.md`.
- Verified by: `npm run check` (license field), `npm run check:features` (superseded entries recorded), the CI workflow on its next push and on `main`, and the M2, M7, M8, M9, M14 and M15 entries named above.

## Update 2026-10-21: the repository is public

The owner made `SimoneRecchia/VibeGlobe` public on 2026-10-21, ahead of the first release. Before relying on that, the agent checked the whole git history (every commit on every branch) for credentials, private keys, environment files and personal contact data, and found none; `GOOGLE_MAPS_API_KEY` still comes only from the environment. The license, README licensing section, contributing guide, security policy and code of conduct are on the development branch and reach the default branch with the merge of the M2 pull request. GitHub-hosted runners are now free for the repository, which [ADR 0022](0022-faster-milestone-process.md) uses to run the long suites in parallel jobs. What remains of F561 is a repository setting only the owner can change: enabling private vulnerability reporting (open question 15).
